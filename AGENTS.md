# AGENTS.md

## About

`agent-root` gives an automation account audited root access to enrolled hosts
through a per-host SSH key that root accepts only from listed addresses and
only through a logging forced command. `bin/agent-root` is the client; the
target side is plain files that `enroll` embeds in a root script, because
enrolled hosts need not have agent-root installed. The README documents the
public contract: commands, host config keys, file layout, and security model.

## Layout

- `bin/agent-root`: the command.
- `lib/agent-root/`: private target-side files, embedded verbatim by
  `enroll`/`revoke`: `agent-root-exec` (forced command), `sshd-match.conf.in`
  (drop-in template), `common.sh` (shared transactional helpers),
  `enroll.sh`, `revoke.sh`. See `lib/agent-root/README.md`.
- `install.sh`: generated; see below.
- `test/`: `run`, `install-test`, `agent-root-{client,exec,target,sshd}-test`,
  `lib/test.sh` (harness). See `test/README.md` for suite scope.

## Invariants

- Root access is the product, so every change must keep the restrictions
  intact: the `from=`, `restrict`, and `command=` key options; the drop-in's
  Match block (`forced-commands-only`, `ForceCommand`, publickey only from
  agent-root's own key file, CA and key-command lookups off, `AcceptEnv`
  narrowed, no tunnels or forwarding) closed by `Match all`; and in
  `agent-root-exec` the log-before-run order, fail-closed logging, full
  logging of every script (oversized ones refused), closed standard input for
  commands, and the minimal child environment. The real-sshd suite proves these;
  run it after touching any of them.
- Every line inside the drop-in's Match block must be printed verbatim by
  `sshd -T`: `enroll.sh` reads the required settings from the installed
  drop-in, so the template is the single source of what enrollment verifies.
- `agent-root-exec` takes no configuration from its environment; the client
  may influence that through `AcceptEnv`.
- Host files are parsed with narrow validators, never sourced. Values reach
  the generated root script only through `printf %q`; the embedded files are
  quoted heredocs. Keep both properties when adding keys.
- Enrollment must not change sshd behavior for any connection except root
  from the enrolled addresses. `enroll.sh` verifies this with `sshd -T`
  before and after; keep that check and the rollback on failure.
- `sshd -T` prints lowercase keywords before OpenSSH 10 and configuration
  spelling from 10 on. Compare through the lowercase normalization in
  `_settings_for`.
- `/usr/local/sbin/agent-root-exec`, `50-agent-root.conf`,
  `/etc/ssh/agent-root/authorized_keys`, the journal tag `agent-root`, the
  `HostKeyAlias` `agent-root-HOST`, and the key comment
  `agent-root:HOST@CLIENT` are on-host contracts that revoke and operators
  rely on. Don't rename them.
- Exit 64 is reserved for usage errors; `run` returns the remote status (255
  for an ssh failure).
- The client stays Bash 3.2-compatible (no `mapfile`, associative arrays, or
  `readlink -f`). CI does not test 3.2; on macOS check with
  `PATH="/bin:$PATH" test/run`.

## Testing

- Local: `test/run`. It lints the inventory's `program` rows when
  `shellcheck` is installed, then runs the suites listed in `test/run`; a new
  suite must be added there.
- Real sshd: `AGENT_ROOT_TEST_REAL_SSHD=1 test/run` (or just
  `test/agent-root-sshd-test`). Needs an OpenSSH server binary; runs it
  unprivileged on a random loopback port.
- CI: `AGENT_ROOT_SKIP_SHELLCHECK=1 test/run` on the full shared matrix with
  the `base,openssh-netcat-lsof` profiles. The real-sshd suite skips there
  because no profile installs an OpenSSH server.

## Test isolation

- Every suite sets `AGENT_ROOT_CONFIG_DIR` under its temporary root; never let
  a test read or write `~/.config/agent-root`.
- Target scripts run against a relocated tree via `AGENT_ROOT_TARGET_ROOT`,
  with `AGENT_ROOT_SSHD` and `AGENT_ROOT_SYSTEMCTL` pointing at fakes. These
  three variables and `AGENT_ROOT_SSH_USER` (the real-sshd suite logs in as
  the current user) are test hooks, not public configuration.
- Never run the enroll or revoke scripts against the real `/` from a test, and
  never as root.
- Fixtures use documentation addresses (`192.0.2.0/24`), `.example` and
  `.invalid` names, and synthetic keys.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`,
  where `<actions@lock>` is a cgraf78/actions checkout at the SHA in
  `.github/cgraf78-actions.lock`.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`; never edit it. Install logic lives in
  `support/install-checkout.sh`. After editing
  `scripts/checkout-installer.conf`, run `consumer-ci/sync.sh <this checkout>`
  from `<actions@lock>`.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename it.
